# 文档结构、混合切分与输出策略

版本：v0.1
状态：目标架构与分阶段实施规范
适用范围：论文、硕博学位论文、技术报告

---

## 1. 决策摘要

LongDoc Translator Agent 不再把 Markdown 当作唯一的文档真相，也不把当前 Chunk Service 描述为完整语义切分。

统一采用以下原则：

```text
原始文件负责可追溯
DocumentIR Lite 负责结构真实性
Chunk Service 负责翻译粒度
Markdown 负责可编辑交换
HTML 负责直接阅读
PDF 路线负责原版对照或重新排版
```

切分策略固定为：

```text
结构边界优先
-> 语义边界辅助
-> token 上限兜底
```

复杂结构输出固定为：

```text
简单且可信的表格       -> GFM Markdown
复杂但结构可信的表格   -> HTML table
低置信度或无法重建表格 -> 原始截图 + CSV/JSON（可用时）+ 风险说明
公式                   -> LaTeX + 编号 + 原始截图兜底
图片                   -> 原图 + caption + 来源页码
```

原始 PDF 必须保留并允许下载，但“返回原始 PDF”不等于生成了翻译 PDF。翻译 PDF 分为后续的双语批注 PDF 和重排中文版 PDF 两条路线。

## 2. 当前实现的真实边界

### 2.1 当前已有能力

当前 Parser 输出已排序的 `ParsedBlock[]`，每个 block 可保存：

- `blockId`
- `kind`
- `text / markdown`
- `order`
- `pageNo / bbox`
- `headingLevel`
- 风险与 Docling 元数据

当前 Chunk Service 已实现：

- 标题作为硬边界。
- 标题后的正文继承最近标题作为 `sectionTitle`。
- 普通 block 按 token 估算合并。
- 超长段落按句号等句界拆分。
- 公式、代码、图片作为原子 chunk。
- 小表保持原子性，大表按完整数据行分组。
- 公式和数字引用在句界拆分时得到保护。
- chunk 来源 block、页面位置和风险可追踪。

### 2.2 当前不具备的能力

当前实现不是 embedding 或 LLM 驱动的完整语义切分，尚未具备：

- 多级标题路径，例如 `Chapter > Method > Training`。
- 相邻段落主题相似度比较。
- 主题突变检测。
- target / soft / hard 三档 token 预算。
- 超长单句的子句级兜底。
- 小碎片的语义回并。
- 可解释的 `boundaryReason / boundaryScore`。
- 结构化表格单元格模型。
- 可持久化的 DocumentIR。

因此当前能力应称为：

> 结构感知、句界保护、token 预算驱动的规则切分基线。

## 3. 为什么不能只保存 Markdown

Markdown 能稳定表达：

- 标题
- 普通段落
- 列表
- 代码块
- 简单公式
- 简单二维表格
- 图片引用

Markdown 不能可靠表达：

- 跨行、跨列表格单元格
- 多级表头
- 跨页续表
- 表格脚注与来源的精确归属
- PDF 中的原始 bbox 和阅读顺序
- 公式 OCR 置信度及原图
- caption 与图片、表格的引用关系
- 双栏与页面级版面信息

即使 GFM 表格语法合法，用户直接查看 Markdown 源码时仍会看到参差不齐的 `|`。空格对齐只能改善源码观感，不能解决中文宽字符、长单元格和不同阅读器兼容性。

因此 Markdown 只能是渲染结果之一，不能作为复杂论文结构的唯一中间表示。

## 4. DocumentIR Lite

### 4.1 定位

`DocumentIR Lite` 是 Parser/Layout Normalizer 与 Chunk Service 之间的可持久化文档中间表示。

第一阶段不引入复杂关系表，使用 JSON 文件保存：

```text
storage/parsed/{jobId}/document.ir.json
```

同时继续生成：

```text
storage/parsed/{jobId}/document.md
```

其中：

- `document.ir.json` 用于结构、切分、渲染和追踪。
- `document.md` 用于调试、快速查看和兼容已有流程。

### 4.2 顶层结构

```json
{
  "version": "1",
  "jobId": "job_xxx",
  "source": {
    "filename": "paper.pdf",
    "mediaType": "application/pdf"
  },
  "sections": [],
  "blocks": [],
  "assets": [],
  "risks": []
}
```

### 4.3 SectionIR

```json
{
  "sectionId": "section_method_training",
  "title": "Training",
  "level": 3,
  "path": ["Method", "Model", "Training"],
  "parentSectionId": "section_model",
  "headingBlockId": "block_000120"
}
```

Parser 遇到标题时维护标题栈：

1. 新标题级别大于栈顶：作为子章节压栈。
2. 新标题级别等于栈顶：替换当前同级标题。
3. 新标题级别小于栈顶：弹栈到对应父级后写入。
4. 正文 block 保存当前 `sectionId` 和完整 `sectionPath`。

### 4.4 BlockIR

BlockIR 在 ParsedBlock 基础上补充稳定结构字段：

```json
{
  "blockId": "block_000121",
  "kind": "paragraph",
  "text": "...",
  "markdown": "...",
  "order": 121,
  "sectionId": "section_method_training",
  "sectionPath": ["Method", "Model", "Training"],
  "pageNo": 8,
  "bbox": null,
  "structure": {},
  "assets": [],
  "risks": []
}
```

### 4.5 持久化原则

- 原始上传文件永久保留到任务被显式删除。
- DocumentIR 写入采用临时文件加原子替换，避免半写文件被 Worker 读取。
- DocumentIR 包含版本号；不兼容版本不得静默恢复旧工作流。
- SQLite 只保存 IR 路径和版本，不保存整份 JSON。
- block 的稳定 ID 用于 chunk、风险、输出资产和原 PDF 位置之间追踪。

## 5. 混合切分算法

### 5.1 第一步：建立不可破坏的结构边界

硬边界包括：

- 标题和章节变化。
- 表格。
- 独立公式。
- 图片和 caption 组合。
- 代码块。
- 参考文献区域与附录边界。
- 高风险版面变化。

硬边界不能被 embedding 相似度覆盖。语义相似也不能把表格合并进普通正文，或把两个章节混成一个 chunk。

### 5.2 第二步：产生正文候选单元

正文以 ParsedBlock/BlockIR 段落为最小语义单元：

- 正常段落不先按字符切碎。
- 列表项保持列表关系。
- 行内公式和引用留在原段落。
- 单段过长时先进行句界拆分。
- 单句仍超过硬上限时，才按子句、分号、逗号或空格兜底，并标记 `LONG_PARAGRAPH`。

### 5.3 第三步：计算候选边界分数

只在同一叶子章节内比较相邻正文单元。

候选信号包括：

- 标题或结构信号。
- 相邻段落词汇重合度。
- 术语和实体连续性。
- 转折、总结、章节承接等话语标记。
- 公式、引用和列表密度变化。
- 可选 embedding 余弦相似度。
- 当前 chunk token 预算。

建议边界数据：

```json
{
  "reason": "SEMANTIC_SHIFT",
  "score": 0.82,
  "signals": {
    "lexicalSimilarity": 0.31,
    "embeddingSimilarity": 0.46,
    "discourseMarker": true,
    "tokenPressure": 0.72
  }
}
```

语义评分服务必须可插拔：

- 基线可以先使用词汇重合、TF-IDF 或其他本地低成本方法。
- embedding 作为增强项，不绑定 DeepSeek；没有 embedding 服务时仍可稳定运行。
- 禁止为了语义切分对每个段落调用昂贵的聊天模型。

### 5.4 第四步：token 预算决策

建议配置：

```text
CHUNK_TARGET_TOKENS=1200
CHUNK_SOFT_MAX_TOKENS=1800
CHUNK_HARD_MAX_TOKENS=2400
```

含义：

- `target`：理想大小，未达到时优先继续合并相关段落。
- `softMax`：超过后优先寻找最近的高分语义边界。
- `hardMax`：除不可拆原子块外必须停止或执行兜底拆分。

决策过程：

1. 小于 target：继续合并同章节且语义连续的段落。
2. 达到 target：遇到较高边界分时结束 chunk。
3. 超过 softMax：回溯选择最近的合适候选边界。
4. 接近 hardMax：必须切分。
5. 原子块超过 hardMax：保持原子并标记风险，不静默破坏结构。

具体默认值需要使用 DeepSeek 实际上下文、Prompt 开销和论文样本校准，不能把启发式 token 当成计费 token。

### 5.5 第五步：小碎片回并

初次切分后检查过小 chunk：

- 必须属于同一章节路径。
- 不能跨原子块或高风险结构边界。
- 与前后 chunk 的语义相似度达到阈值。
- 合并后不能超过 softMax。

满足条件时与更相关的一侧回并，减少只有标题或一两句话的无效请求。

### 5.6 可解释边界

每个 chunk 保存：

```text
sectionPath
boundaryReason
boundaryScore
semanticTopic（可选）
sourceBlockIds
tokenEstimate
```

`boundaryReason` 建议枚举：

```text
SECTION_BOUNDARY
ATOMIC_BLOCK
SEMANTIC_SHIFT
TOKEN_SOFT_LIMIT
TOKEN_HARD_LIMIT
TABLE_GROUP
END_OF_DOCUMENT
```

## 6. 表格结构与渲染

### 6.1 TableIR

复杂表格必须保存单元格结构，而不只是 pipe 字符串：

```json
{
  "tableId": "table_001",
  "caption": "Table 1. Results",
  "cells": [
    {
      "row": 0,
      "column": 0,
      "rowSpan": 2,
      "columnSpan": 1,
      "text": "Method",
      "isHeader": true
    }
  ],
  "footnotes": [],
  "pageRange": [7, 8],
  "confidence": 0.91,
  "sourceAssetId": "asset_table_001",
  "renderMode": "HTML"
}
```

### 6.2 表格分级策略

#### GFM

仅用于：

- 单层表头。
- 无合并单元格。
- 单元格内容简短。
- 行列数和解析置信度在允许范围内。

GFM 输出需要格式化，但不能承诺源码视觉完全对齐。

#### HTML

用于：

- `rowspan / colspan`。
- 多级表头。
- 单元格内换行、公式或列表。
- 结构可信但 GFM 无法表达的表格。

Markdown 文件可嵌入 HTML table；独立 HTML 输出使用统一 CSS 渲染。

#### Image fallback

用于：

- 表格结构解析置信度低。
- 跨页合并关系无法可靠恢复。
- 列错位或 OCR 严重异常。

输出包含：

- 原始表格截图。
- caption。
- 页码。
- 风险提示。
- 可可靠导出的 CSV/JSON（若存在）。

禁止为了看起来整齐而猜测性重建错误表格。

### 6.3 表格翻译

- caption、header、普通文本单元格可翻译。
- 数字、单位、公式和引用按保护规则处理。
- 大表可以按完整数据行分组供模型处理，但输出必须基于同一 TableIR 合并。
- 为模型重复的 caption/header 标记 `syntheticRepeat=true`，最终只渲染正确次数。

## 7. 公式、图片与引用

### 7.1 FormulaIR

```json
{
  "formulaId": "formula_001",
  "latex": "L(\\theta)=-\\sum_i y_i \\log p_i",
  "number": "3",
  "pageNo": 8,
  "bbox": null,
  "confidence": 0.88,
  "sourceAssetId": "asset_formula_001"
}
```

规则：

- 优先保存 LaTeX。
- 公式符号、编号和引用不翻译。
- 只翻译公式周围解释文字。
- LaTeX 低置信度时保留公式截图并标记风险。
- HTML 输出使用 KaTeX 或 MathJax；Markdown 输出保留 `$...$ / $$...$$`。

### 7.2 FigureIR

图片保存：

- 原始图片资产。
- caption 原文与译文。
- page/bbox。
- 正文引用关系。
- OCR/解析风险。

MVP 不翻译图片内部文字，但不能丢弃图片或 caption。

### 7.3 引用

- 数字引用和作者年份引用保持原样。
- 参考文献条目不与正文混切。
- 交叉引用在输出时尽量保留原编号。
- MVP 不验证文献真实性。

## 8. 输出分层

### 8.1 Markdown 输出

继续生成：

- `bilingual.md`
- `translated.md`
- `report.md`

定位：

- 可编辑。
- 可搜索。
- 可版本控制。
- 适合作为交换格式。

不承诺所有阅读器都能完美渲染 HTML 表格、公式和相对资源。

### 8.2 HTML 阅读输出

目标增加：

- `bilingual.html`
- `translated.html`

定位：

- 用户直接阅读的首选格式。
- 统一表格样式。
- KaTeX/MathJax 公式渲染。
- 图片和 caption 布局。
- 风险提示和原页定位。

HTML 输出进入 MVP 输出增强阶段，不得在实现前由前端显示可用按钮。

### 8.3 结果包

目标生成：

```text
result.zip
├── bilingual.html
├── translated.html
├── bilingual.md
├── translated.md
├── report.md
├── original.pdf 或原始上传文件
├── manifest.json
└── assets/
    ├── tables/
    ├── formulas/
    └── figures/
```

`manifest.json` 记录输出文件、媒体类型、资产关联和校验信息。

结果包解决 Markdown 单文件无法携带图片、表格截图和其他相对资源的问题。

### 8.4 原始文件

原始上传文件必须可单独下载，也必须包含在结果包中。

对于 PDF：

- 原始 PDF 完整返回。
- 不修改原始文件。
- 不把原始 PDF 称为“翻译 PDF”。

## 9. PDF 路线

### MVP

- 保留并下载原始 PDF。
- 生成 Markdown、HTML 和结果包。
- 通过 page/bbox 和资产关联保持可追溯。

### V1：双语批注 PDF

- 原 PDF 页面保持不变。
- 在页边栏、注释层或附加译文页放置中文。
- 使用 bbox 将译文与原文区域关联。
- 不尝试用中文直接覆盖英文。

### V2：重排中文版 PDF

- 从 DocumentIR 重新排版。
- 保留公式、图片、表格和交叉引用。
- 中文分页允许与原 PDF 不同。
- 可采用 HTML/CSS Paged Media、Typst 或 LaTeX 渲染。

直接覆盖原 PDF 英文不是推荐路线，因为中英文长度差异会造成溢出、重叠和分页错误。

## 11. 分阶段实施

### 阶段 A：当前规则基线

- 已完成结构化 ParsedBlock。
- 已完成标题硬边界、句界拆分和原子块保护。
- 已完成大表按完整数据行分组。

### 阶段 B：结构真实性

- 实现标题栈和 `sectionPath`。
- 实现 DocumentIR Lite 文件持久化。
- 实现 TableIR / FormulaIR / FigureIR 最小结构。
- 保存原始表格、公式和图片资产。

### 阶段 C：混合切分

- 增加 target / soft / hard token 预算。
- 增加 `boundaryReason / boundaryScore`。
- 增加本地词汇相似度基线。
- 增加可插拔 embedding scorer。
- 增加超长单句兜底和小碎片回并。

### 阶段 D：输出增强

- 实现 GFM / HTML / image fallback 表格渲染。
- 实现公式 HTML 渲染。
- 生成两个 HTML 阅读文件。
- 生成 manifest 和 result.zip。
- 增加原始文件下载。

### 阶段 E：PDF

- V1 双语批注 PDF。
- V2 重排中文版 PDF。

## 12. 验收原则

- 结构不能为了满足 token 阈值被静默破坏。
- 语义评分失败时必须回退到结构规则基线。
- 每个 chunk 能解释为何在该位置切分。
- 复杂表格不能伪装成可信的简单 Markdown 表格。
- 用户不依赖特定 Markdown 编辑器，也能通过 HTML 或结果包阅读完整内容。
- 原始 PDF、页码、bbox 和输出资产之间可追踪。
- 低置信度内容优先保留原始证据并提示复核。
---

## 13. 渲染与资源安全

HTML 和结果包由用户上传文档派生，必须按不可信输入处理：

- 段落、caption、表格单元格和文件名默认 HTML escape。
- 只允许 Render Service 生成的标签白名单，不直接透传源 Markdown 中的 `<script>`、事件属性、iframe 或任意内联脚本。
- KaTeX/MathJax、CSS 和图片优先本地打包，独立 HTML 不依赖未知远程资源。
- URL 只允许安全的相对资产路径或明确允许的协议。
- ZIP 内文件名经过规范化，拒绝 `..`、绝对路径、盘符和路径穿越。
- 解压后的所有引用必须保持在结果目录内。
- 原始文件下载使用安全 `Content-Disposition` 文件名，不信任用户上传文件名作为服务器路径。
- manifest 中记录的路径必须通过同一套路径校验。

MVP 没有多用户权限系统，但仍需防止输出文件在浏览器中执行源文档携带的恶意内容。
