# LongDoc Translator Agent Gradio UI 设计

版本：v1.0
状态：当前实现规范
入口：`/ui`

## 1. 工作台定位

Gradio 是正式操作台。用户完成登录后可以创建多个后台任务、关闭页面、稍后重新登录，并继续审核或下载结果。业务状态只保存在 PostgreSQL 和对象存储，不依赖浏览器生命周期。

```text
登录
-> 左侧历史任务 / 新建任务
-> 右侧概览、术语、风险、人工审核、时间线、输出
```

## 2. 页面结构

登录页：用户名、密码、登录、注册。退出登录只删除当前会话，不取消后台任务。

工作台左侧：

- 当前账号与退出按钮。
- 该用户自己的任务列表。
- 刷新、恢复、取消。
- 上传 PDF/Markdown/TXT。
- 论文/小说模式、十种目标语言、PDF OCR 模式。
- 可选高风险和章节人工审核。

工作台右侧：

- 任务状态、队列位置、chunk 进度、ETA、源/目标语言、当前阶段和最后更新时间。
- 概览：chunk 序号、章节、结构类型、状态、token 和复核提示。
- 术语：不展示数据库 ID，只展示原术语、建议译名、确认译名和备注。
- 风险：问题名称、严重度、页码/章节、原因、原文片段、系统处理和建议操作。
- 人工审核：使用可读位置，不暴露 review/subject ID。
- 时间线：阶段名称、状态、耗时和错误说明。
- 输出：优先 HTML 和结果包，同时提供 Markdown、报告和原文件。

## 3. 状态规则

- `gr.State` 只保存当前 session token 和 `job_id`，每次事件都重新鉴权并查询 PostgreSQL。
- `gr.Timer` 每 2 秒刷新活动任务。
- 页面关闭不发送取消请求；只有“取消”按钮会写入 `CANCELLED`。
- ETA 由近期 chunk 调用耗时中位数估算，样本不足显示“正在估算”。
- 排队任务显示队列位置。
- 风险和状态除颜色外必须有文字说明。

## 4. 视觉规范

- 安静、工作导向的桌面工作台，不使用营销 hero 或装饰性卡片堆叠。
- 左侧固定任务与创建区域，右侧是可扫描的数据区。
- 页面背景浅灰、内容表面白色、青绿色主操作、琥珀色提醒、红色危险操作。
- 卡片圆角不超过 8px；表格允许横向滚动。
- 1280px 桌面和 390px 移动端不得出现控件重叠或不可访问文本。

## 5. 安全边界

- handler 直接复用 Service，不通过内部 HTTP 调用自身 API。
- 每次 handler 调用使用会话 token 获取用户，并校验任务所有权。
- Gradio 不展示或允许编辑 `job_id/term_id/review_id/chunk_id` 等内部标识。
- 下载只返回该用户任务的本地受控文件或 S3 短期签名 URL。

## 6. 验收

- 注册、登录、注销和重新登录可用。
- 用户只能看到自己的任务。
- 上传后任务进入后台队列，关闭页面后继续。
- 重新登录后可以继续术语/风险审核并下载完成结果。
- 进度、ETA、队列、风险和时间线使用真实数据库数据。
- HTML、结果包、Markdown、报告和原文件下载可用。
- REST API 与 Gradio 同时可用。
