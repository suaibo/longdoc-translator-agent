# LongDoc Translator Agent 前端 UI 与交互规范

版本：v0.3
状态：MVP 实现规范
适用范围：论文翻译模式
依据：`需求文档.md`、`架构设计.md`、`接口说明.md`、`数据库设计.md`、`测试计划.md`

---

## 1. 文档定位

本文档由外部 UI 蓝图评审修订而来，用于约束 LongDoc Translator Agent 的 React Web 控制台实现和前端验收。

设计目标不是展示一个通用 AI 产品，而是让用户清楚、可信地完成以下工作流：

```text
任务列表
-> 新建任务并上传文档
-> 解析、版面标准化与切块
-> 术语人工确认
-> 分块翻译与进度查看
-> 失败后从检查点恢复
-> 下载双语稿、中文稿和风险报告
```

MVP 必须突出：

- 长任务所处阶段和进度。
- 术语确认这一 Human-in-the-Loop 中断点。
- chunk 级处理状态和论文结构风险。
- 已完成结果不丢失的失败恢复能力。
- 可编辑 Markdown、直接阅读 HTML、原始文件与结果资源包的分层交付。

本文档描述目标 MVP，不代表所有接口和页面已经实现。前端开发必须以接口实际可用情况分模块推进，不使用伪造数据掩盖缺失能力。

## 2. 评审后的范围调整

相较初始设计稿，本版做出以下约束：

### 2.1 补充

- 增加任务列表页，对应 `GET /api/jobs`。
- 增加 PDF 的 `ocrMode` 选择，仅暴露 `auto / off / force`。
- 增加单任务队列忙 `40902` 的处理和返回运行中任务的路径。
- 增加真实论文风险类型：表格、公式、引用、结构、长段落、解析警告。
- 增加页面刷新后根据任务状态恢复正确视图的规则。
- 增加空术语表直接确认、轮询退避、陈旧数据提示和响应式验收。

### 2.2 删除或后置

- 删除独立 Logo 设计、复杂品牌动画和卡片悬浮上移。
- 删除自动弹出的 Bottom Drawer；失败信息改为任务详情内的固定错误区域。
- 删除逐 chunk 重试、日志入口和完整原文/译文复制，因为 MVP 没有对应接口。
- 删除“最近检查点时间”“当前章节”“失败次数”等当前接口未返回的数据。
- 删除小说模式的可操作入口；只保留禁用说明，不模拟功能。
- 删除原生 JavaScript 全局状态示例；项目使用 React + TypeScript。

### 2.3 修正

- 新建任务页不是 `UPLOADED` 状态；只有创建成功后的任务才进入该状态。
- `PARSED` 表示解析与切块已经完成，不能用于表示“正在识别章节”。处理中页面应同时展示 `status` 与 `currentStage`。
- chunk 状态使用 `PENDING / TRANSLATING / COMPLETED / FAILED / SKIPPED`，不存在 `CANCELLED` chunk。
- 术语确认请求只提交 `termId / confirmedTranslation / note`，不回传 `source` 或 `suggested`。
- Chunk 详情当前只能使用接口提供的 120 字预览；完整结构预览需要后续接口。表格预览不得把原始 pipe 文本当作最终视觉效果。

## 3. 信息架构与路由

```text
AppShell
├── /jobs                  任务列表（默认入口）
├── /jobs/new              新建翻译任务
└── /jobs/:jobId           任务详情状态容器
    ├── UPLOADED / PARSED             处理中
    ├── WAITING_TERM_REVIEW           术语确认
    ├── TRANSLATING                   翻译进度
    ├── FAILED                        失败与恢复
    ├── COMPLETED                     结果下载
    └── CANCELLED                     已取消
```

任务详情使用同一路由按服务端状态渲染，不为每个状态制造独立 URL。刷新、复制链接或重新进入页面时，必须先查询任务详情，再决定展示哪个视图。

全局导航只提供：

- `任务列表`
- `新建任务`

MVP 不展示用户头像、通知、团队、额度、模型市场或设置入口。

## 4. 视觉与布局原则

### 4.1 产品气质

界面应像研究工具和任务控制台：安静、紧凑、可扫描。避免营销型 Hero、过量卡片、装饰渐变和大面积单一紫色。

建议色彩：

| Token | 色值 | 用途 |
| --- | --- | --- |
| `brand-600` | `#2563EB` | 主操作、链接、活动状态 |
| `brand-50` | `#EFF6FF` | 选中背景 |
| `accent-700` | `#0F766E` | 完成强调、次级重点 |
| `neutral-950` | `#111827` | 主文字 |
| `neutral-700` | `#374151` | 正文 |
| `neutral-500` | `#6B7280` | 辅助文字 |
| `neutral-200` | `#E5E7EB` | 边框与分隔线 |
| `neutral-50` | `#F9FAFB` | 页面背景 |
| `success` | `#15803D` | 完成 |
| `warning` | `#B45309` | 等待与风险 |
| `danger` | `#B91C1C` | 失败与取消确认 |

状态不能只靠颜色表达，必须同时使用图标或文字。

### 4.2 排版

```css
font-family: Inter, -apple-system, BlinkMacSystemFont, "Segoe UI",
  "Microsoft YaHei", "PingFang SC", sans-serif;
```

| 层级 | 字号 / 行高 | 用途 |
| --- | --- | --- |
| H1 | `24px / 34px` | 页面主标题 |
| H2 | `16px / 24px` | 页面分区标题 |
| Body | `14px / 22px` | 正文和表格 |
| Caption | `12px / 18px` | 时间与辅助字段 |

不按视口宽度缩放字号。任务 ID、文件名和章节名允许省略，但必须可通过 Tooltip 或详情区域查看完整值。

### 4.3 页面结构

- 顶部导航高度：`56px`。
- 内容最大宽度：`1280px`。
- 页面边距：桌面 `24px`，窄屏 `16px`。
- 页面区块间距：`24px`。
- 控件圆角：`6px`；卡片最大圆角：`8px`。
- 阴影仅用于 Dialog 和 Drawer；常规内容使用边框和分隔线。
- 不在卡片内部继续嵌套卡片。

响应式规则：

- `>= 1024px`：完整桌面布局。
- `768-1023px`：侧栏和主区改为上下排列。
- `< 768px`：表格使用横向滚动或转换为键值行，按钮不溢出。

### 4.4 图标和动效

- 按钮优先使用 Lucide 图标：上传、下载、刷新、取消、恢复、查看。
- 图标按钮必须有 Tooltip 和 `aria-label`。
- 普通过渡 `120-200ms`，不使用循环流光、缩放或页面大幅位移。
- `prefers-reduced-motion` 下关闭非必要动画。

## 5. 全局状态模型

### 5.1 任务状态

| 状态 | 用户文案 | 主视图 | 可用操作 |
| --- | --- | --- | --- |
| `UPLOADED` | 已上传，等待处理 | 处理中 | 取消 |
| `PARSED` | 已完成解析与切块 | 处理中 | 取消 |
| `WAITING_TERM_REVIEW` | 等待术语确认 | 术语确认 | 确认术语、取消 |
| `TRANSLATING` | 翻译中 | 翻译进度 | 取消 |
| `COMPLETED` | 已完成 | 结果下载 | 下载 |
| `FAILED` | 任务失败 | 失败与恢复 | 恢复 |
| `CANCELLED` | 已取消 | 已取消 | 返回列表 |

`currentStage` 用于细化状态，不替代 `status`。建议映射：

| currentStage | 用户文案 |
| --- | --- |
| `uploaded` | 文件已保存 |
| `parse_document` | 正在解析文档 |
| `split_sections` | 正在整理章节与分块 |
| `extract_terms` | 正在抽取术语 |
| `interrupt_for_term_review` | 等待术语确认 |
| `translate_chunk` | 正在翻译分块 |
| `summarize_chunk_context` | 正在更新上下文摘要 |
| `mark_risks` | 正在汇总风险 |
| `generate_outputs` | 正在生成译文 |
| `generate_report` | 正在生成报告 |

未知阶段显示后端原值，不推测不存在的步骤。

### 5.2 Chunk 状态

| 状态 | 用户文案 |
| --- | --- |
| `PENDING` | 等待中 |
| `TRANSLATING` | 翻译中 |
| `COMPLETED` | 已完成 |
| `FAILED` | 失败 |
| `SKIPPED` | 已跳过 |

### 5.3 风险类型

| 风险 | 显示文案 | 说明 |
| --- | --- | --- |
| `TABLE` | 表格结构 | 可能包含分组、跨页或行列结构风险 |
| `FORMULA` | 公式 | 公式符号、编号或 OCR 可能需要复核 |
| `REFERENCE` | 引用 | 引用编号或作者年份格式可能异常 |
| `STRUCTURE` | 版面结构 | 双栏重排、caption 归属等结构调整 |
| `LONG_PARAGRAPH` | 长段落 | 已进入句界切分或需要复核 |
| `PARSER_WARNING` | 解析警告 | OCR、bbox、乱码或解析置信度问题 |

风险提示应表述为“建议复核”，不能暗示系统已经自动修复所有问题，也不能默认阻塞翻译。

## 6. 任务列表页

### 6.1 页面目标

默认入口用于查看历史任务、继续当前任务和创建新任务。

顶部布局：

```text
翻译任务                              [新建任务]
查看任务状态、继续术语确认或下载结果。
```

列表字段：

| 字段 | 数据来源 |
| --- | --- |
| 文件名 | `originalFilename` |
| 状态 | `status` |
| 当前阶段 | `currentStage` |
| 进度 | `completedChunks / totalChunks`、`progressPercent` |
| 更新时间 | `updatedAt` |
| 操作 | 查看任务 |

规则：

- 默认按 `updatedAt` 倒序。
- 行点击和“查看”按钮都进入 `/jobs/{jobId}`。
- 不提供删除、批量操作和筛选器；任务量增长后再引入。
- 列表为空时展示简洁空状态和“新建任务”按钮。
- 请求失败时保留已有列表，并提供手动重试。

## 7. 新建任务页

### 7.1 基本表单

表单包含：

1. 翻译模式：固定为 `学术论文`，提交值 `paper`。
2. 单文件上传：`.pdf / .md / .txt`，最大 `50MB`。
3. OCR 模式：仅在选择 PDF 后展示。
4. 提交按钮：`创建翻译任务`。

小说模式不作为可选卡片展示。若需要表达规划，只在模式说明中写“当前仅支持学术论文”。

### 7.2 OCR 模式

使用单选组或 Select：

| 值 | 文案 | 说明 |
| --- | --- | --- |
| `auto` | 自动（推荐） | 优先读取 PDF 文本，需要时启用 OCR |
| `off` | 关闭 OCR | 适合可复制文字的 PDF，处理更快 |
| `force` | 强制 OCR | 适合扫描版 PDF，耗时更长 |

默认 `auto`。Markdown 和 TXT 不显示 OCR 控件，提交时可省略或使用 `auto`，后端忽略非 PDF 的 OCR 模式。

### 7.3 上传交互

- 支持点击选择和拖拽单个文件。
- 已选文件显示文件名、大小、类型和移除按钮。
- 多文件只接受第一个属于隐式行为，禁止；应明确提示单文件限制。
- 校验失败后保留表单其他选择。
- 提交中禁用文件、OCR 和提交按钮，避免重复创建。

错误文案：

| 场景 | 文案 |
| --- | --- |
| 格式不支持 | 仅支持 PDF、Markdown 和 TXT 文件。 |
| 文件过大 | 文件超过 50MB，请选择较小的文件。 |
| 多文件 | 每个任务只能上传一个文件。 |
| 队列忙 `40902` | 当前已有任务正在运行，请先查看或结束该任务。 |

创建请求：

```http
POST /api/jobs
Content-Type: multipart/form-data

file=<file>
mode=paper
ocrMode=auto
```

成功后只依赖返回的 `jobId` 跳转任务详情，不假定任务已经进入 `PARSED`。

## 8. 处理中视图

对应 `UPLOADED / PARSED`，使用一个阶段区和任务摘要，不使用伪百分比。

展示：

- 文件名。
- 当前状态和阶段。
- 已知 chunk 数；尚未生成时显示 `—`。
- 创建时间、更新时间。
- 取消任务按钮。

阶段表示例：

```text
文件已保存            完成
文档解析              进行中
章节与分块            等待
术语抽取              等待
术语确认              等待
```

只根据 `status/currentStage` 标记完成和进行中，不用前端计时器模拟处理进度。

轮询 `GET /api/jobs/{jobId}`：前台每 2 秒；页面隐藏后降低到 10 秒；上一次请求未完成时不重复发起。

## 9. 术语确认视图

对应 `WAITING_TERM_REVIEW`。

桌面端可采用 `280px + minmax(0, 1fr)` 两栏：左侧任务摘要，右侧术语表。窄屏改为上下布局。任务摘要不显示接口没有提供的章节数或文档类型字段。

术语表字段：

| 字段 | 规则 |
| --- | --- |
| 原术语 | 只读 `sourceTerm` |
| Agent 建议 | 只读 `suggestedTranslation` |
| 确认译名 | 可编辑 `confirmedTranslation`，默认使用建议译名 |
| 备注 | 可选 `note` |

提交请求：

```json
{
  "terms": [
    {
      "termId": "term_001",
      "confirmedTranslation": "检查点",
      "note": "保留技术术语译法"
    }
  ]
}
```

规则：

- 确认译名去除首尾空白后不能为空。
- 提交期间禁用重复操作。
- 离开存在未提交修改的页面时弹出确认 Dialog。
- 空术语表显示“未识别到需要确认的术语”，仍调用同一确认接口继续流程；不在前端直接篡改任务状态。
- 确认成功后重新查询任务详情，再进入翻译视图。

## 10. 翻译进度视图

对应 `TRANSLATING`。

### 10.1 顶部摘要

展示接口真实字段：

- `progressPercent`
- `completedChunks / totalChunks`
- `currentStage`
- `updatedAt`

不展示当前章节、检查点时间、真实 token 消耗或运行时长，除非后续接口明确增加这些字段。

### 10.2 Chunk 列表

字段：

| 列 | 内容 |
| --- | --- |
| 编号 | `chunkIndex + 1` |
| 章节 | `sectionTitle`，空值显示“未命名章节” |
| 类型 | `chunkType` |
| 状态 | Chunk 状态标签 |
| 风险 | `riskTypes / riskSummary`；无风险时显示“无” |
| 原文预览 | `sourcePreview` |
| 译文预览 | `translatedPreview`，未生成时显示 `—` |
| 完成时间 | `translatedAt` |

MVP 操作仅为“查看预览”。点击后可打开右侧 Drawer，展示接口已有预览、状态和风险。不要命名为“查看完整原文/译文”，不要提供逐 chunk 重试或日志按钮。

结构预览增强后：

- `TABLE` 优先渲染 GFM/HTML 结果，不向普通用户直接展示参差不齐的 pipe 源码。
- 低置信度表格展示原始截图、caption、页码和“建议复核”。
- `FORMULA` 使用 KaTeX/MathJax 渲染，失败时展示 LaTeX 和原始截图。
- `PICTURE` 展示原图与 caption。
- 用户可切换“渲染结果 / 原始结构文本”，但默认是渲染结果。

任务详情每 2 秒、chunk 列表每 3 秒轮询，两个请求错开；终态停止。更新列表时保持滚动位置和已打开 Drawer，不整页闪烁。

## 11. 失败与恢复视图

对应 `FAILED`，仍在任务详情页内展示，不自动弹出遮挡内容的 Bottom Drawer。

错误区展示：

- `errorCode`
- `errorMessage`
- 已完成 chunk 数和总数
- 已完成 chunk 列表保持原状态
- `从检查点恢复` 按钮

调用：

```http
POST /api/jobs/{jobId}/resume
```

规则：

- 不把网络轮询失败误判为任务 `FAILED`。
- 恢复请求成功后重新查询任务详情；只有服务端返回 `TRANSLATING` 才恢复轮询。
- 前端不自动无限恢复，不提供逐 chunk 重试。
- 若 `resume` 返回 `40902`，提示当前有其他运行任务。
- 如果后端没有可用检查点，以接口错误信息为准，不虚构检查点编号和时间。

---

## 12. 完成与下载视图

对应 `COMPLETED`。

基础阶段展示三个 Markdown 输出；输出增强后根据 `GET /api/jobs/{jobId}/outputs` 返回的可用清单动态展示：

| 优先级 | 类型 | 文件 | 说明 |
| --- | --- | --- | --- |
| 推荐 | `bilingual_html` | `bilingual.html` | 双语直接阅读，正确渲染表格和公式 |
| 推荐 | `translated_html` | `translated.html` | 中文连续阅读 |
| 推荐 | `package` | `result.zip` | 包含原始文件、HTML、Markdown 和全部资产 |
| 次级 | `bilingual` | `bilingual.md` | 可编辑双语交换格式 |
| 次级 | `translated` | `translated.md` | 可编辑中文交换格式 |
| 次级 | `report` | `report.md` | 术语、风险、耗时和调用指标 |
| 追溯 | `source` | 原始文件 | 原始 PDF/MD/TXT，不是翻译文件 |

界面应明确：Markdown 需要兼容阅读器才能正确渲染表格；复杂论文优先推荐 HTML 或结果包。

下载按钮使用 Download 图标并显示明确文件名。文件请求失败：

- `40402`：文件不存在或尚未生成。
- `40901`：任务状态不允许下载。
- 网络错误：保留按钮并允许用户重试。

完成页提供“返回任务列表”和“新建任务”，不自动删除旧任务。

---

## 13. 已取消视图

对应 `CANCELLED`。

展示任务已停止和已完成 chunk 数。MVP 不允许恢复取消任务，也不下载未完成输出。提供“返回任务列表”。

取消任务使用确认 Dialog。`COMPLETED` 不显示取消按钮；`CANCELLED` 不重复调用取消接口。后台只保证在 chunk 边界停止，因此确认文案应说明“当前步骤结束后停止”。

## 14. 全局反馈与异常

### 14.1 网络异常

- 请求失败不清空最近一次成功数据。
- 页面顶部展示非阻塞提示：“暂时无法获取最新状态，正在重试。”
- 连续失败采用有限退避，例如 2 秒、5 秒、10 秒，恢复后回到正常间隔。
- 提供手动刷新按钮。

### 14.2 任务不存在

展示“未找到该任务”，提供返回任务列表，不自动创建替代任务。

### 14.3 Toast 与 Dialog

Toast 只用于短反馈；需要用户决策或长期存在的信息放在页面正文。

Dialog 用于：

- 取消任务确认。
- 离开未提交术语页确认。

默认焦点位于安全操作，支持 `Esc`，关闭后恢复触发元素焦点。

## 16. 可访问性

- 所有功能可通过键盘完成。
- 拖拽上传必须同时支持标准文件选择按钮。

## 19. 结构化内容阅读体验

### 19.1 表格

用户界面不以 Markdown 源码中的 `|` 是否对齐作为表格质量标准。

展示优先级：

1. 可交互或静态 HTML table。
2. 简单表格的浏览器原生渲染结果。
3. 低置信度时的原始截图。
4. 原始 pipe/JSON 只放在“结构详情”中供调试。

表格区域需要：

- 横向滚动，不压缩到无法阅读。
- sticky header（长表可选）。
- caption、来源页码和风险提示。
- 对重复 header/caption 做最终渲染去重。
- 不把图片 fallback 描述成已完成结构重建。

### 19.2 公式

- HTML 预览使用 KaTeX 或 MathJax。
- 渲染失败时显示原始 LaTeX，并允许查看公式截图。
- 公式编号与正文引用可见。
- 不提供普通文本输入框让用户误改公式结构。

### 19.3 原始 PDF

任务详情和完成页可以提供“查看/下载原始文件”。

- 原始 PDF 在新标签或浏览器 PDF Viewer 打开。
- 文案必须写“原始 PDF”，不能写“翻译 PDF”。
- 后续双语批注 PDF 上线后使用独立输出类型和说明。

### 19.4 输出能力渐进开放

前端通过输出清单决定按钮，不假设所有任务都有 HTML 或 package：

- 旧任务只有 Markdown 时正常显示。
- 新任务生成 HTML 后将 HTML 标为推荐。
- package 未生成时不显示假按钮。
- 相对资产缺失时展示明确错误，不回退成破损图片。

### 19.5 HTML 安全

- 前端不使用未清洗的 `dangerouslySetInnerHTML` 渲染源文档内容。
- HTML 预览只加载后端 Render Service 生成并清洗后的文件。
- 新标签打开独立 HTML 时使用安全响应头，不允许源文档脚本执行。
- 外部链接明确标识；本地图片和公式资源失败时显示占位与错误信息。
