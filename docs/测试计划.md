# LongDoc Translator Agent 测试计划

版本：v0.1  
适用范围：MVP 论文翻译模式

---

## 1. 测试目标

测试目标是验证 LongDoc Translator Agent 的 MVP 能稳定完成以下闭环：

```text
上传文档
-> 解析文档
-> 切分 chunk
-> 抽取术语
-> 人工确认术语
-> 分块翻译
-> 写入检查点
-> 生成输出文件
-> 下载结果
```

重点验证：

- 状态流转正确。
- 术语确认能中断和恢复工作流。
- chunk 级翻译能保存进度。
- 失败后能从检查点继续。
- 表格和公式风险能进入报告。
- 前端能通过轮询完成完整演示。

---

## 2. 测试环境

### 2.1 本地环境

- Python 3.11+
- Node.js 20+
- SQLite
- Docling 可正常运行
- OpenAI-compatible LLM API Key

### 2.2 测试数据

建议准备：

- `samples/sample-paper.md`
  - 包含标题、摘要、章节、术语、表格。
- `samples/sample-long.txt`
  - 长文本，包含多个段落。
- `samples/sample-paper.pdf`
  - 简短论文 PDF，用于 Docling 解析测试。
- `samples/sample-bad.pdf`
  - 损坏或不可解析 PDF，用于失败测试。

## 3. 单元测试

### 3.1 文档解析

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 解析 Markdown | `sample-paper.md` | 返回 Markdown 原文或标准化 Markdown |
| 解析 TXT | `sample-long.txt` | 转换为 Markdown 段落 |
| 解析 PDF | `sample-paper.pdf` | Docling 输出结构化 Markdown |
| 解析失败 PDF | `sample-bad.pdf` | 抛出解析失败错误 |

### 3.2 章节与段落切分

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 有标题 Markdown | `# / ##` 标题 | 按章节归类 chunk |
| 无标题 TXT | 多段文本 | 归入默认章节 |
| 长段落 | 超过 chunk 阈值 | 只在句子边界拆分，公式和引用标记不被截断 |
| 小表格 | 未超过行数和 token 阈值 | caption 与表格保持一个原子 chunk |
| 大表格 | 超过行数或 token 阈值 | 按完整数据行分组，每组重复 caption/header |
| 独立公式或代码 | 超过 chunk 阈值 | 仍保持原子 chunk，不机械截断 |
| 多章节文档 | 多级标题与正文 | 标题开启章节，正文继承正确 sectionTitle |

### 3.3 风险识别

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| Markdown 表格 | `| col | col |` | 标记 `TABLE` 风险 |
| 公式文本 | `$...$` 或 `\(...\)` | 标记 `FORMULA` 风险 |
| 引用密集文本 | `[1]`、`(Smith, 2020)` | 标记 `REFERENCE` 风险 |
| 超长段落 | 大段无换行文本 | 标记 `LONG_PARAGRAPH` 风险 |

### 3.4 术语表处理

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| LLM 返回合法 JSON | 术语数组 | 正确解析为 term_entry |
| LLM 返回重复术语 | 重复 sourceTerm | 去重或覆盖同一术语 |
| 用户确认术语 | confirmedTranslation | 保存并标记 confirmed |
| 缺少确认译名 | 空 confirmedTranslation | 返回参数校验失败 |

### 3.5 状态流转

| 用例 | 初始状态 | 操作 | 期望状态 |
| --- | --- | --- | --- |
| 上传成功 | 无 | 创建任务 | `UPLOADED` |
| 解析成功 | `UPLOADED` | parse + split | `PARSED` |
| 术语抽取完成 | `PARSED` | extract_terms | `WAITING_TERM_REVIEW` |
| 确认术语 | `WAITING_TERM_REVIEW` | PUT terms | `TRANSLATING` |
| 翻译完成 | `TRANSLATING` | 完成所有 chunk | `COMPLETED` |
| 解析失败 | `UPLOADED` | parse error | `FAILED` |
| 用户取消 | 运行中 | cancel | `CANCELLED` |

### 3.6 输出文件生成

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 完成任务 | chunks + terms + risks | 生成 3 个 Markdown 文件 |
| 双语输出 | 原文 + 译文 | 保留章节顺序 |
| 中文输出 | 译文 | 不包含原文段落 |
| 报告输出 | metrics + terms + risks | 包含进度、术语、风险、耗时 |

### 3.7 Chunk Service 持久化

| 用例 | 期望 |
| --- | --- |
| 相同 blocks 重复切块 | chunk ID 稳定，不增加重复记录和风险项 |
| PENDING chunk 重新切分 | 允许更新并删除多余 PENDING chunk |
| 已处理 chunk 重新切分 | 返回 `40901`，不覆盖译文和状态 |
| ParsedBlock 风险继承 | chunk 和 risk_item 均保存风险与来源元数据 |
| Docling caption 引用 | 即使 caption 不相邻，也能通过引用关联表格 |
| 旧 SQLite 启动 | 自动新增 chunk 结构列和 risk metadata 列 |

## 4. 集成测试

### 4.1 Markdown 完整流程

步骤：

1. 上传 `sample-paper.md`。
2. 后端创建任务。
3. 自动解析、切分、抽取术语。
4. 任务进入 `WAITING_TERM_REVIEW`。
5. 提交确认术语。
6. 完成所有 chunk 翻译。
7. 生成输出文件。

期望：

- 任务最终为 `COMPLETED`。
- chunk 全部为 `COMPLETED`。
- 输出文件可下载。

### 4.2 TXT 长文流程

步骤：

1. 上传 `sample-long.txt`。
2. 检查默认章节是否生成。
3. 确认术语。
4. 完成翻译。

期望：

- 文本按段落分块。
- 译文顺序和原文一致。

### 4.3 PDF 解析流程

步骤：

1. 上传 `sample-paper.pdf`。
2. Docling 解析为 Markdown。
3. 进入同一切分和术语流程。

期望：

- `parsed_markdown_path` 不为空。
- 任务进入 `WAITING_TERM_REVIEW`。

### 4.4 LLM 失败恢复

步骤：

1. 模拟第 N 个 chunk 翻译失败。
2. 检查前 N-1 个 chunk 已保存。
3. 任务进入 `FAILED`。
4. 调用 `POST /api/jobs/{jobId}/resume`。
5. 从第 N 个 chunk 继续。

期望：

- 已完成 chunk 不重复翻译。
- 最终任务可完成。

### 4.5 取消任务

步骤：

1. 启动翻译任务。
2. 翻译中调用取消接口。
3. 后台 worker 在 chunk 边界停止。

期望：

- 任务状态为 `CANCELLED`。
- 不再继续处理后续 chunk。

## 5. API 测试

### 5.1 创建任务

- 上传合法 Markdown，返回 `jobId`。
- 上传非法扩展名，返回 `40002`。
- 上传超过 50MB 文件，返回 `40003`。
- 有运行中任务时再次上传，返回 `40902`。

### 5.2 查询任务

- 查询存在任务，返回 `JobVO`。
- 查询不存在任务，返回 `40401`。

### 5.3 查询和确认术语

- `GET /terms` 返回术语数组。
- `PUT /terms` 可保存用户确认译名。
- 非 `WAITING_TERM_REVIEW` 状态确认术语，返回 `40901`。
- 缺少确认译名，返回 `40001`。

### 5.4 查询分块

- 返回 chunk 顺序、章节、`chunkType`、状态、`riskTypes` 和风险摘要。
- 不存在任务返回 `40401`。

### 5.5 下载结果

- `COMPLETED` 状态可下载 3 个文件。
- 未完成任务下载返回 `40901`。
- 文件缺失返回 `40402`。

### 5.6 恢复和取消

- `FAILED` 状态可调用 `resume`。
- 非 `FAILED` 状态调用 `resume` 返回 `40901`。
- 运行中任务可取消。
- `COMPLETED` 任务取消返回 `40901`。

## 6. 前端交互测试

### 6.1 上传页

- 可以选择 PDF / MD / TXT。
- 选择 PDF 时显示 `auto / off / force` OCR 模式，默认 `auto`；MD / TXT 不显示。
- 上传成功后跳转任务详情页。
- 上传失败时显示错误信息。
- 单任务队列忙时提示并引导查看当前任务。

### 6.2 任务详情页

- 展示文件名、状态、阶段、进度。
- 每 2 秒轮询任务详情。
- 状态更新后 UI 同步刷新。

### 6.3 术语表确认页

- 状态为 `WAITING_TERM_REVIEW` 时展示术语表。
- 用户可以编辑译名。
- 确认后进入翻译阶段。

### 6.4 翻译进度页

- 展示 chunk 列表。
- 展示已完成 / 翻译中 / 失败状态。
- 风险 chunk 有明显标记。
- 失败时展示恢复按钮。

### 6.5 结果下载页

- `COMPLETED` 后展示 3 个下载按钮。
- 下载文件名正确。

## 8. 暂不测试内容

MVP 暂不覆盖：

- 多用户隔离。
- 多任务并发。
- DOCX / HTML / PDF 导出。
- 小说模式人物记忆。
- 每章人工确认。
- 风险片段逐条人工确认。
- 大规模性能压测。

本周最低交付需要满足：

- Markdown 样例能跑通完整流程。
- Web 控制台能展示术语确认中断点。
- chunk 级进度可见。
- 至少一种失败恢复路径可演示。
- 三个输出文件可下载。

## 10. Parser + Layout Normalizer 补充验收

| 用例 | 期望 |
| --- | --- |
| Markdown 表格 | 整张表保留为一个 `TABLE` block，并标记表格风险 |
| 双栏 PDF blocks | 同页按左栏从上到下、再右栏从上到下输出，并标记结构风险 |
| 重复页眉页脚 | 按跨页重复文本或 Docling 标签过滤，不进入翻译正文 |
| 超长段落 | 保持正文并标记 `LONG_PARAGRAPH`，交给 ChunkService 按句拆分 |
| 公式 | 保留原公式文本并标记 `FORMULA` |
| 引用密集段落 | 标记 `REFERENCE` |
| 损坏 PDF | Docling 失败统一转换为业务错误码 `50002` |
| OCR 模式 | `auto / off / force` 可构造对应 Docling pipeline，其他值返回 `40001` |
