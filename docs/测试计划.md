# LongDoc Translator Agent 测试计划

版本：v0.3
适用范围：MVP 论文翻译模式

---

## 1. 测试目标

测试目标是验证 LongDoc Translator Agent 的 MVP 能稳定完成以下闭环：

```text
上传文档
-> 解析文档
-> 切分 chunk
-> 抽取术语
-> 人工确认术语
-> 分块翻译
-> 写入检查点
-> 生成输出文件
-> 下载结果
```

重点验证：

- 状态流转正确。
- 术语确认能中断和恢复工作流。
- chunk 级翻译能保存进度。
- 失败后能从检查点继续。
- 表格和公式结构不被普通切分破坏，低置信度内容保留原始证据并进入报告。
- Gradio 能通过轮询读取 PostgreSQL 真实状态并完成演示。

## 2. 测试环境

### 2.1 本地环境

- Python 3.11+
- Docker Desktop
- PostgreSQL 16 开发库与独立测试库
- Docling 可正常运行

### 2.2 测试数据

建议准备：

- `samples/sample-paper.md`
  - 包含标题、摘要、章节、术语、表格。

- `samples/sample-semantic-sections.md`
  - 同一章节内包含连续主题、主题突变、超长单句和短段落。

## 3. 单元测试

### 3.1 文档解析

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 解析 Markdown | `sample-paper.md` | 返回 Markdown 原文或标准化 Markdown |
| 解析 TXT | `sample-long.txt` | 转换为 Markdown 段落 |
| 解析 PDF | `sample-paper.pdf` | Docling 输出结构化 Markdown |
| 解析失败 PDF | `sample-bad.pdf` | 抛出解析失败错误 |

### 3.2 章节与段落切分

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 有标题 Markdown | `# / ##` 标题 | 按章节归类 chunk |
| 无标题 TXT | 多段文本 | 归入默认章节 |
| 长段落 | 超过 chunk 阈值 | 只在句子边界拆分，公式和引用标记不被截断 |
| 小表格 | 未超过行数和 token 阈值 | caption 与表格保持一个原子 chunk |
| 大表格 | 超过行数或 token 阈值 | 按完整数据行分组，每组重复 caption/header |
| 独立公式或代码 | 超过 chunk 阈值 | 仍保持原子 chunk，不机械截断 |
| 多章节文档 | 多级标题与正文 | 生成完整 sectionPath |

### 3.3 风险识别

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| Markdown 表格 | `| col | col |` | 标记 `TABLE` 风险 |
| 公式文本 | `$...$` 或 `\(...\)` | 标记 `FORMULA` 风险 |
| 引用密集文本 | `[1]`、`(Smith, 2020)` | 标记 `REFERENCE` 风险 |
| 超长段落 | 大段无换行文本 | 标记 `LONG_PARAGRAPH` 风险 |

### 3.4 术语表处理

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| LLM 返回合法 JSON | 术语数组 | 正确解析为 term_entry |
| LLM 返回重复术语 | 重复 sourceTerm | 去重或覆盖同一术语 |
| 用户确认术语 | confirmedTranslation | 保存并标记 confirmed |
| 缺少确认译名 | 空 confirmedTranslation | 返回参数校验失败 |

### 3.5 状态流转

| 用例 | 初始状态 | 操作 | 期望状态 |
| --- | --- | --- | --- |
| 上传成功 | 无 | 创建任务 | `UPLOADED` |
| 解析成功 | `UPLOADED` | parse + split | `PARSED` |
| 术语抽取完成 | `PARSED` | extract_terms | `WAITING_TERM_REVIEW` |
| 确认术语 | `WAITING_TERM_REVIEW` | PUT terms | `TRANSLATING` |
| 翻译完成 | `TRANSLATING` | 完成所有 chunk | `COMPLETED` |
| 解析失败 | `UPLOADED` | parse error | `FAILED` |
| 用户取消 | 运行中 | cancel | `CANCELLED` |

### 3.6 输出文件生成

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 完成任务 | chunks + terms + risks | 基础生成 3 个 Markdown；增强生成 HTML、manifest 和 result.zip |
| 双语输出 | 原文 + 译文 | 保留章节顺序、结构资产和相对链接 |
| 中文输出 | 译文 | 不包含原文段落 |
| 报告输出 | metrics + terms + risks | 包含进度、术语、风险、耗时 |

### 3.7 Chunk Service 持久化

| 用例 | 期望 |
| --- | --- |
| 相同 blocks 重复切块 | chunk ID 稳定，不增加重复记录和风险项 |
| PENDING chunk 重新切分 | 允许更新并删除多余 PENDING chunk |
| 已处理 chunk 重新切分 | 返回 `40901`，不覆盖译文和状态 |
| ParsedBlock 风险继承 | chunk 和 risk_item 均保存风险与来源元数据 |
| Docling caption 引用 | 即使 caption 不相邻，也能通过引用关联表格 |
| Alembic 初始迁移 | 从空 PostgreSQL 创建六张核心表与索引 |
| PostgreSQL 原生类型 | JSONB、BOOLEAN、TIMESTAMPTZ 类型正确 |
| 多任务创建 | 多个活动任务可同时入库和排队 |
| 队列租约 | Worker 原子领取任务并在完成后清理队列项 |
| 节点时间预算 | 超时节点返回 504 业务失败并记录失败事件 |
| LangGraph checkpointer | PostgreSQL checkpoint 表可保存并恢复中断线程 |
| 工作流事件 | 节点开始、完成、中断和失败事件按时间写入 PostgreSQL |
| token/费用预算 | 达到任务上限后拒绝下一次 LLM 调用并返回明确错误 |
| 模型路由 | 翻译等任务使用对应专用模型配置，未配置时回退默认模型 |
| 供应商 fallback | 仅可重试错误耗尽后切换一次备用供应商 |
| 有限修订 | HIGH 质量问题按上限修订并复检，不形成无限循环 |
| 小说记忆 | 人物固定译名与章节摘要跨 chunk 持久化并可回读 |
| 结构子图 | 表格行、公式分隔符和引用标记损坏可被专用子图识别 |
| replay 脱敏 | 默认 JSONL 不包含原文/译文，只保留哈希和评测字段 |
| 离线评测 | 脚本输出完成率、风险率和修订次数 |
| 高风险审核 | HIGH 风险创建持久化请求并进入 `WAITING_RISK_REVIEW` |
| 章节审核 | 仅在章节最后一个 chunk 后中断，批准后继续原线程 |

### 3.8 Gradio

| 用例 | 期望 |
| --- | --- |
| `/ui` 挂载 | 返回 Gradio 页面，FastAPI `/api` 同时可用 |
| handler 创建任务 | Gradio 临时文件进入统一 JobService |
| 页面加载/刷新 | 同时更新任务下拉框与当前 `job_id` |
| 定时轮询 | 从 PostgreSQL 读取任务、chunk、术语和风险 |
| 工作流时间线 | 展示节点状态、耗时、中断与失败说明 |
| 人工审核 | 展示待审核对象、类型和状态，可填写备注并批准继续 |
| 输出下载 | 只返回真实存在的文件 |
| 响应式 | 1280px 与 390px 无控件重叠，窄屏标签可折叠 |

### 3.9 Agent 与输出

| 用例 | 期望 |
| --- | --- |
| DeepSeek JSON | 术语和质量结果通过 Pydantic 校验 |
| 瞬时错误 | 按指数退避有限重试，并记录 retry_count |
| 术语 interrupt | 首次运行停在 `WAITING_TERM_REVIEW` |
| `Command(resume)` | 确认术语后从原 LangGraph 线程继续 |

| HTML 安全 | 源文档脚本被转义，不执行事件属性 |
| result.zip | 不包含绝对路径、盘符或 `..` |

## 4. 集成测试

### 4.1 Markdown 完整流程

步骤：

1. 上传 `sample-paper.md`。
2. 后端创建任务。
3. 自动解析、切分、抽取术语。
4. 任务进入 `WAITING_TERM_REVIEW`。
5. 提交确认术语。
6. 完成所有 chunk 翻译。
7. 生成输出文件。

期望：

- 任务最终为 `COMPLETED`。
- chunk 全部为 `COMPLETED`。
- 输出文件可下载。

### 4.2 TXT 长文流程

步骤：

1. 上传 `sample-long.txt`。
2. 检查默认章节是否生成。
3. 确认术语。
4. 完成翻译。

期望：

- 文本按段落分块。
- 译文顺序和原文一致。

### 4.3 PDF 解析流程

步骤：

1. 上传 `sample-paper.pdf`。
2. Docling 解析为 Markdown。
3. 进入同一切分和术语流程。

期望：

- `parsed_markdown_path` 不为空。
- 任务进入 `WAITING_TERM_REVIEW`。

### 4.4 LLM 失败恢复

步骤：

1. 模拟第 N 个 chunk 翻译失败。
2. 检查前 N-1 个 chunk 已保存。
3. 任务进入 `FAILED`。
4. 调用 `POST /api/jobs/{jobId}/resume`。
5. 从第 N 个 chunk 继续。

期望：

- 已完成 chunk 不重复翻译。
- 最终任务可完成。

### 4.5 取消任务

步骤：

1. 启动翻译任务。
2. 翻译中调用取消接口。
3. 后台 worker 在 chunk 边界停止。

期望：

- 任务状态为 `CANCELLED`。
- 不再继续处理后续 chunk。

## 5. API 测试

### 5.1 创建任务

- 上传合法 Markdown，返回 `jobId`。
- 上传非法扩展名，返回 `40002`。
- 上传超过 50MB 文件，返回 `40003`。
- 有运行中任务时再次上传，新任务仍可创建并排队。

### 5.2 查询任务

- 查询存在任务，返回 `JobVO`。
- 查询不存在任务，返回 `40401`。

### 5.3 查询和确认术语

- `GET /terms` 返回术语数组。
- `PUT /terms` 可保存用户确认译名。
- 非 `WAITING_TERM_REVIEW` 状态确认术语，返回 `40901`。
- 缺少确认译名，返回 `40001`。

### 5.4 查询分块

- 返回 chunk 顺序、章节、`chunkType`、状态、`riskTypes` 和风险摘要。
- 不存在任务返回 `40401`。

### 5.5 下载结果

- `COMPLETED` 状态可下载 3 个基础 Markdown；输出增强实现后可下载 HTML 和 result.zip。
- 未完成任务下载返回 `40901`。
- 文件缺失返回 `40402`。

### 5.6 恢复和取消

- `FAILED` 状态可调用 `resume`。
- 非 `FAILED` 状态调用 `resume` 返回 `40901`。
- 运行中任务可取消。
- `COMPLETED` 任务取消返回 `40901`。

## 11. DocumentIR 与混合切分测试（目标）

### 11.1 标题树与正文归属

| 用例 | 期望 |
| --- | --- |
| `# A -> ## B -> ### C` | C 下正文的 `sectionPath` 为 `[A, B, C]` |
| 同级标题切换 | 新正文不继承前一个同级标题 |
| 标题降级 | 标题栈正确弹出到父级 |
| 无标题文档 | 使用空路径或默认根章节，不伪造标题 |
| 只有标题没有正文 | 小碎片回并或保留可解释边界，不丢标题 |

### 11.2 语义边界

| 用例 | 期望 |
| --- | --- |
| 同主题相邻段落 | 未达到 target 时优先合并 |
| DeepSeek 返回 SPLIT | 在同章节普通正文内产生 `LLM_SEMANTIC_SPLIT` |
| DeepSeek 边界判断失败 | 有限重试后回退规则切分，记录 BOUNDARY_MODEL_FAILED |
| 结构边界两侧语义相似 | 仍不跨标题、表格、公式等硬边界合并 |
| 无疑似边界 | 不调用 DeepSeek，直接进入规则切分 |

### 11.3 token 预算

| 用例 | 期望 |
| --- | --- |
| 小于 target | 继续尝试合并 |
| 超过 softMax | 回溯到最近合适语义边界 |
| 接近 hardMax | 必须切分并记录原因 |
| 单句超过 hardMax | 按子句或安全标点兜底，保留公式和引用 |
| 原子表格超过 hardMax | 不拆单元格，保留原子或按完整行分组并标风险 |
| 过小 chunk | 只在同 section 且不跨硬边界时回并 |

### 11.4 可解释性

每个新 chunk 验证：

- `sourceBlockIds` 可回溯。
- `sectionPath` 正确。
- `boundaryReason` 属于约定枚举。
- 语义边界存在合法 `boundaryScore`。
- 硬边界允许 `boundaryScore=null`。
- 相同输入重复构建保持稳定 ID 与边界原因。

## 12. 复杂结构与输出测试（目标）

### 12.1 表格分级渲染

| 用例 | 期望 |
| --- | --- |
| 简单单层表头 | 输出合法 GFM，渲染器显示真实表格 |
| GFM 源码列宽不同 | 不以 pipe 字符源码对齐作为验收标准 |
| 多级表头/合并单元格 | 输出 HTML table，rowspan/colspan 正确 |
| 单元格包含公式或列表 | HTML 输出结构完整 |
| 低置信度表格 | 输出原始截图、caption、页码和风险提示 |
| 可可靠导出矩形数据 | 同时生成 CSV/JSON 资产 |
| 大表分组 | 翻译请求可重复 header，最终输出按 tableGroupId 去重 |
| 跨页续表 | 无法可靠恢复时不猜测合并，保留证据和风险 |

### 12.2 公式与图片

| 用例 | 期望 |
| --- | --- |
| 高置信度 LaTeX | Markdown 保留 LaTeX，HTML 正确渲染 |
| 公式编号 | 编号和正文引用保持一致 |
| 低置信度公式 | 附原始截图并标 `FORMULA` 风险 |
| 图片与 caption | 相对路径有效，caption 译文不与图片脱离 |
| 图片内部文字 | MVP 不翻译，但原图不丢失 |

### 12.3 输出包

验证 `result.zip` 至少包含：

```text
bilingual.html
translated.html
bilingual.md
translated.md
report.md
manifest.json
original.ext
assets/
```

并检查：

- 所有相对链接解压后有效。
- manifest 中媒体类型和路径正确。
- 原始 PDF 字节保持不变。
- HTML 在无后端环境下可打开。
- Markdown 缺少外部阅读器时仍可作为文本查看，但 UI 不把它宣传为最佳视觉输出。
- caption/单元格中的 `<script>`、事件属性和 iframe 不会进入可执行 HTML。
- ZIP 拒绝 `../evil`、绝对路径和 Windows 盘符路径。
- manifest 不引用输出根目录外的文件。

### 12.4 PDF 路线

MVP 只测试原 PDF 完整下载，不测试翻译 PDF。

V1 双语批注 PDF 需要额外验证：

- 原页面不被覆盖。
- bbox 与译文关联正确。
- 长译文不会遮挡原文、公式和表格。

V2 重排中文版 PDF 单独建立版式回归测试，不与当前 MVP 混用。

## 13. 账号、后台任务和云存储测试

| 用例 | 期望 |
| --- | --- |
| 注册/登录/注销 | scrypt 密码验证；注销 token 立即失效 |
| 未登录访问任务 | 返回 401 |
| 用户访问他人任务 | 返回 404，不能读取术语、风险或下载 |
| 关闭页面/退出登录 | Worker 继续运行，任务不取消 |
| 重新登录 | 历史任务、进度和下载恢复 |
| 同用户提交 6 个任务 | 最多 5 个有效租约，第 6 个排队 |
| 多 Worker 同时领取 | `FOR UPDATE SKIP LOCKED` 保证不重复执行 |
| Worker 崩溃 | 租约过期后重领并从 checkpoint 恢复 |
| S3 模式 Web 无本地文件 | 下载接口签发短期 URL，不要求本地副本 |
| 对象 key 含 `..` | 拒绝路径穿越 |
| 输出校验持续失败 | 最多重试 2 次后任务 FAILED，不形成死循环 |

## 14. 多语言与可读风险测试

- 自动检测中文、英文、日文、韩文、俄文和阿拉伯文脚本。
- 十种 `targetLanguage` 可创建任务，Prompt 明确携带目标语言。
- 风险 UI 不展示数据库 ID，必须包含问题、位置、原因、系统处理和建议。
- `CONTINUE/SPLIT/UNCERTAIN` 均有路由测试；UNCERTAIN 和模型失败必须进入报告。
## 2026-06-28 测试增补摘要

新增测试重点：

- 模型白名单解析、默认模型、非法模型拒绝。
- 术语确认后任务进入 `WAITING_STYLE_REVIEW`，预翻译生成后等待风格确认。
- 风格 Prompt 被传入预翻译和正式翻译，但不覆盖结构保护规则。
- 用户编辑 chunk 会追加版本历史、更新当前译文并设置 `outputs_stale=true`。
- 历史版本恢复会追加 `RESTORE` 版本并标记输出过期。
- `workflow_event.event_seq` 支持 `after` 查询和 SSE 断线续传。
- stream token 绑定 `userId + jobId + exp`，过期或任务不匹配时拒绝。
