# LongDoc Translator Agent 数据库设计

版本：v0.3
数据库：PostgreSQL 16
迁移工具：Alembic
适用范围：MVP 论文翻译模式

## 1. 设计原则

- PostgreSQL 是唯一受支持的关系数据库，不保留 SQLite 兼容路径。
- schema 只能通过 Alembic 升级，应用启动不执行 `create_all()`。
- 时间使用 `TIMESTAMPTZ`，布尔值使用 `BOOLEAN`，结构化状态使用 `JSONB`。
- 状态值使用字符串，由应用枚举和业务校验约束，暂不使用 PostgreSQL Enum。
- 上传文件、DocumentIR 和输出资产保存在文件系统，数据库保存路径、索引和任务状态。
- chunk 结果、术语、风险、指标和 checkpoint 独立保存，支持恢复与追踪。

## 2. 核心表

### 2.1 `translation_job`

保存任务元数据和总体进度。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `job_id` | varchar PK | 任务 ID |
| `original_filename` | varchar | 原始文件名 |
| `original_file_path` | varchar | 上传文件路径 |
| `parsed_markdown_path` | varchar nullable | 标准化 Markdown 路径 |
| `document_ir_path/document_ir_version` | varchar nullable | DocumentIR 路径与版本 |
| `output_manifest_path` | varchar nullable | 输出 manifest 路径 |
| `mode` | varchar | MVP 固定为 `paper` |
| `ocr_mode` | varchar | `auto/off/force` |
| `workflow_version/prompt_version` | varchar | 恢复兼容与 Prompt 追踪 |
| `status` | varchar | 任务状态 |
| `current_stage` | varchar | 当前工作流节点 |
| `total_chunks` | integer | chunk 总数 |
| `completed_chunks` | integer | 已完成 chunk 数 |
| `progress_percent` | double precision | 进度百分比 |
| `error_code/error_message` | varchar nullable | 失败信息 |
| `retry_count` | integer | 任务恢复次数 |
| `max_token_budget` | integer | 任务累计 token 上限，`0` 表示禁用 |
| `max_cost_usd` | double precision | 任务估算费用上限，`0` 表示禁用 |
| `require_high_risk_review` | boolean | 是否启用高风险 chunk 审核 |
| `require_chapter_review` | boolean | 是否启用章节结束审核 |
| 时间字段 | timestamptz | 创建、更新、开始、完成、取消时间 |

索引：

- `idx_translation_job_status`
- `idx_translation_job_created_at`
- `uq_translation_job_one_active`

`uq_translation_job_one_active` 是 PostgreSQL 部分唯一索引：当状态属于 `UPLOADED / PARSED / WAITING_TERM_REVIEW / TRANSLATING` 时，全库最多存在一个活动任务。Service 的预检查用于友好提示，数据库索引用于解决并发竞态。

### 2.2 `document_chunk`

保存结构化分块和译文。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `chunk_id` | varchar PK | 稳定 chunk ID |
| `job_id` | varchar FK | 所属任务 |
| `chunk_index` | integer | 任务内顺序 |
| `section_title` | varchar nullable | 最近章节标题 |
| `chunk_type` | varchar | `TEXT/TABLE/FORMULA/PICTURE/CODE` |
| `source_text` | varchar | 原文 |
| `source_block_ids` | jsonb | 来源 block ID |
| `structure_metadata` | jsonb | 页码、bbox、表格分组等 |
| `section_path` | jsonb | 完整章节路径 |
| `boundary_reason` | varchar nullable | 切分原因 |
| `boundary_score` | double precision nullable | 语义边界评分 |
| `semantic_topic` | varchar nullable | 可解释主题词 |
| `translated_text` | varchar nullable | 译文 |
| `context_summary` | varchar nullable | 滑动窗口摘要 |
| `status` | varchar | chunk 状态 |
| `has_risk` | boolean | 是否存在风险 |
| `risk_summary` | varchar nullable | 风险摘要 |
| `token_estimate` | integer | 本地 token 估算 |
| `revision_count` | integer | 质量检查触发的有限修订次数 |
| 时间字段 | timestamptz | 创建、更新、翻译完成时间 |

约束：`UNIQUE(job_id, chunk_index)`。

### 2.3 `term_entry`

保存术语建议与人工确认结果。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `term_id` | varchar PK | 术语 ID |
| `job_id` | varchar FK | 所属任务 |
| `source_term` | varchar | 原文术语 |
| `suggested_translation` | varchar | Agent 建议 |
| `confirmed_translation` | varchar nullable | 人工确认译名 |
| `note` | varchar nullable | 备注 |
| `confirmed` | boolean | 是否确认 |
| 时间字段 | timestamptz | 创建和更新时间 |

约束：`UNIQUE(job_id, source_term)`。

### 2.4 `agent_checkpoint`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `checkpoint_id` | varchar PK | 检查点 ID |
| `job_id` | varchar FK | 所属任务 |
| `thread_id` | varchar | LangGraph thread ID |
| `current_node` | varchar | 当前节点 |
| `chunk_index` | integer nullable | 当前 chunk |
| `state_snapshot` | jsonb | 可恢复状态 |
| `created_at` | timestamptz | 创建时间 |

### 2.5 `translation_metric`

保存 provider、model、真实 token 用量、耗时、重试、失败次数和
`estimated_cost_usd`。费用根据环境变量中的每百万输入/输出 token 单价估算；
单价为 `0` 时仍保留 token 指标，但费用为 `0`。`chunk_id` 删除时设为
`NULL`，任务删除时级联删除。

### 2.6 `risk_item`

保存表格、公式、引用、结构、长段落和解析异常风险。`metadata_json` 使用 JSONB 保存来源 block、页码、bbox 和表格分组信息。

### 2.7 `workflow_event`

记录每个 LangGraph 节点的 `STARTED / COMPLETED / INTERRUPTED / FAILED`
事件、耗时、错误说明和 JSONB 元数据。该表用于 Gradio 时间线、失败节点定位
和后续 replay 数据构建，不替代 LangGraph checkpoint。

### 2.8 LangGraph checkpointer 表

`checkpoints`、`checkpoint_blobs` 和 `checkpoint_writes` 由
`langgraph-checkpoint-postgres` 使用。表结构由 Alembic 管理，不在应用启动时
临时建表。业务可读审计继续写入 `agent_checkpoint`。

### 2.9 `review_request`

持久化 `HIGH_RISK_CHUNK / CHAPTER` 审核请求、审核对象、状态、JSONB 快照、
处理备注和处理时间。`UNIQUE(job_id, review_type, subject_id)` 防止节点恢复时
重复创建同一审核；任务删除时级联删除。

### 2.10 `story_memory` 与 `chapter_memory`

`story_memory` 以任务、实体类型和原名唯一保存人物、地点、设定的固定译名及
首次/最近出现 chunk。`chapter_memory` 按章节路径保存最长 2000 字符的连续摘要。
两表只在 `novel` 模式更新，并在后续 chunk 翻译时回注上下文。

## 3. 状态约定

任务状态：

```text
UPLOADED
PARSED
WAITING_TERM_REVIEW
TRANSLATING
COMPLETED
FAILED
CANCELLED
```

chunk 状态：

```text
PENDING
TRANSLATING
COMPLETED
FAILED
SKIPPED
```

正常流转：

```text
UPLOADED -> PARSED -> WAITING_TERM_REVIEW -> TRANSLATING -> COMPLETED
```

失败保留已完成 chunk 和 checkpoint；取消在 chunk 边界停止。

## 4. 迁移与运行

初始迁移：

```text
backend/alembic/versions/20260624_0001_initial_postgresql.py
backend/alembic/versions/20260624_0002_workflow_and_langgraph.py
backend/alembic/versions/20260624_0003_events_and_budgets.py
backend/alembic/versions/20260624_0004_human_reviews.py
backend/alembic/versions/20260624_0005_model_routing_and_revision.py
backend/alembic/versions/20260624_0006_novel_memory.py
```

执行：

```powershell
cd backend
$env:PYTHONPATH=(Get-Location).Path
..\.venv\Scripts\python.exe -m alembic upgrade head
```

规则：

- 每次 ORM schema 变更必须同时增加 Alembic revision。
- CI/本地测试必须从迁移生成数据库结构，不能使用 `Base.metadata.create_all()` 代替。
- 当前不迁移旧 SQLite 数据；旧 `storage/app.db` 不再读取。
- 生产部署先执行迁移，再启动应用。

## 5. 文件系统边界

```text
storage/uploads/{jobId}/original.ext
storage/parsed/{jobId}/document.md
storage/parsed/{jobId}/document.ir.json
storage/outputs/{jobId}/bilingual.md
storage/outputs/{jobId}/translated.md
storage/outputs/{jobId}/report.md
```

DocumentIR 保持版本化 JSON，不拆成逐 block 关系表。后续新增 `document_ir_path`、`document_ir_version`、`output_manifest_path` 等字段时必须通过 Alembic。
