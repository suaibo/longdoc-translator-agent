# LongDoc Translator Agent 数据库设计

版本：v0.2
数据库：SQLite  
适用范围：MVP 论文翻译模式

---

## 1. 设计原则

MVP 使用 SQLite 保存任务状态、文档分块、术语表、检查点、风险项和翻译指标；原始文件、DocumentIR、结构资产和输出文件保存到文件系统。

设计原则：

- 原始文件、DocumentIR JSON、表格/公式/图片资产和导出文件保存到文件系统，数据库只保存路径、版本和索引字段。
- chunk 级翻译结果入库，便于续跑和进度展示。
- 术语表独立保存，便于 Human-in-the-Loop 编辑确认。
- 检查点独立保存，便于恢复失败任务。
- 状态枚举使用文本字段，降低 MVP 实现成本。

## 3. 表结构

### 3.1 translation_job

保存翻译任务元信息。

```sql
CREATE TABLE translation_job (
    job_id TEXT PRIMARY KEY,
    original_filename TEXT NOT NULL,
    original_file_path TEXT NOT NULL,
    parsed_markdown_path TEXT,
    mode TEXT NOT NULL DEFAULT 'paper',
    status TEXT NOT NULL,
    current_stage TEXT NOT NULL,
    total_chunks INTEGER NOT NULL DEFAULT 0,
    completed_chunks INTEGER NOT NULL DEFAULT 0,
    progress_percent REAL NOT NULL DEFAULT 0,
    error_code TEXT,
    error_message TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    started_at TEXT,
    completed_at TEXT,
    cancelled_at TEXT
);
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| job_id | 任务 ID，例如 `job_20260623_xxx` |
| original_filename | 用户上传时的原始文件名 |
| original_file_path | 原始文件保存路径 |
| parsed_markdown_path | 标准化调试 Markdown 路径；不是复杂结构的唯一真相 |
| mode | MVP 固定为 `paper` |
| status | 任务状态 |
| current_stage | 当前阶段，例如 `extract_terms` |
| total_chunks | chunk 总数 |
| completed_chunks | 已完成 chunk 数 |
| progress_percent | 翻译进度百分比 |
| error_code | 失败错误码 |
| error_message | 失败原因 |

索引：

```sql
CREATE INDEX idx_translation_job_status ON translation_job(status);
CREATE INDEX idx_translation_job_created_at ON translation_job(created_at DESC);
```

### 3.2 document_chunk

保存文档分块和翻译结果。

```sql
CREATE TABLE document_chunk (
    chunk_id TEXT PRIMARY KEY,
    job_id TEXT NOT NULL,
    chunk_index INTEGER NOT NULL,
    section_title TEXT,
    chunk_type TEXT NOT NULL DEFAULT 'TEXT',
    source_text TEXT NOT NULL,
    source_block_ids TEXT NOT NULL DEFAULT '[]',
    structure_metadata TEXT NOT NULL DEFAULT '{}',
    translated_text TEXT,
    context_summary TEXT,
    status TEXT NOT NULL DEFAULT 'PENDING',
    has_risk INTEGER NOT NULL DEFAULT 0,
    risk_summary TEXT,
    token_estimate INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    translated_at TEXT,
    FOREIGN KEY (job_id) REFERENCES translation_job(job_id) ON DELETE CASCADE,
    UNIQUE (job_id, chunk_index)
);
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| chunk_id | 分块 ID |
| job_id | 所属任务 |
| chunk_index | 当前任务内的顺序号，从 0 开始 |
| section_title | 当前实现保存最近章节标题；目标增加完整 section_path |
| chunk_type | `TEXT / TABLE / FORMULA / PICTURE / CODE` |
| source_text | 原文内容 |
| source_block_ids | JSON 数组，记录来源 ParsedBlock ID |
| structure_metadata | JSON 对象，记录页面、bbox、block 类型、表格分组及目标边界元数据 |
| translated_text | 中文译文 |
| context_summary | 当前 chunk 翻译后的摘要，用于滑动窗口记忆 |
| has_risk | 是否存在风险片段 |
| risk_summary | 风险摘要 |
| token_estimate | 预估 token 数 |

索引：

```sql
CREATE INDEX idx_document_chunk_job ON document_chunk(job_id);
CREATE INDEX idx_document_chunk_status ON document_chunk(job_id, status);
```

### 3.3 term_entry

保存术语表。

```sql
CREATE TABLE term_entry (
    term_id TEXT PRIMARY KEY,
    job_id TEXT NOT NULL,
    source_term TEXT NOT NULL,
    suggested_translation TEXT NOT NULL,
    confirmed_translation TEXT,
    note TEXT,
    confirmed INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    FOREIGN KEY (job_id) REFERENCES translation_job(job_id) ON DELETE CASCADE,
    UNIQUE (job_id, source_term)
);
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| source_term | 原术语 |
| suggested_translation | Agent 建议译名 |
| confirmed_translation | 用户确认或编辑后的译名 |
| confirmed | 是否已确认 |
| note | 备注，可记录术语上下文 |

索引：

```sql
CREATE INDEX idx_term_entry_job ON term_entry(job_id);
```

### 3.4 agent_checkpoint

保存 Agent 检查点。

```sql
CREATE TABLE agent_checkpoint (
    checkpoint_id TEXT PRIMARY KEY,
    job_id TEXT NOT NULL,
    thread_id TEXT NOT NULL,
    current_node TEXT NOT NULL,
    chunk_index INTEGER,
    state_snapshot TEXT NOT NULL,
    created_at TEXT NOT NULL,
    FOREIGN KEY (job_id) REFERENCES translation_job(job_id) ON DELETE CASCADE
);
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| thread_id | LangGraph thread ID |
| current_node | 当前节点名 |
| chunk_index | 当前处理到的 chunk 顺序 |
| state_snapshot | JSON 字符串，保存工作流状态 |

索引：

```sql
CREATE INDEX idx_agent_checkpoint_job ON agent_checkpoint(job_id, created_at DESC);
```

### 3.5 translation_metric

保存翻译调用指标。

```sql
CREATE TABLE translation_metric (
    metric_id TEXT PRIMARY KEY,
    job_id TEXT NOT NULL,
    chunk_id TEXT,
    provider TEXT,
    model TEXT,
    prompt_tokens INTEGER NOT NULL DEFAULT 0,
    completion_tokens INTEGER NOT NULL DEFAULT 0,
    total_tokens INTEGER NOT NULL DEFAULT 0,
    elapsed_ms INTEGER NOT NULL DEFAULT 0,
    retry_count INTEGER NOT NULL DEFAULT 0,
    failed_count INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL,
    FOREIGN KEY (job_id) REFERENCES translation_job(job_id) ON DELETE CASCADE,
    FOREIGN KEY (chunk_id) REFERENCES document_chunk(chunk_id) ON DELETE SET NULL
);
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| provider | 模型服务商，例如 `openai-compatible` |
| model | 模型名 |
| prompt_tokens | 输入 token |
| completion_tokens | 输出 token |
| elapsed_ms | 调用耗时 |
| retry_count | 当前调用重试次数 |
| failed_count | 当前调用失败次数 |

索引：

```sql
CREATE INDEX idx_translation_metric_job ON translation_metric(job_id);
CREATE INDEX idx_translation_metric_chunk ON translation_metric(chunk_id);
```

### 3.6 risk_item

保存风险片段。

```sql
CREATE TABLE risk_item (
    risk_id TEXT PRIMARY KEY,
    job_id TEXT NOT NULL,
    chunk_id TEXT,
    risk_type TEXT NOT NULL,
    severity TEXT NOT NULL DEFAULT 'MEDIUM',
    message TEXT NOT NULL,
    source_excerpt TEXT,
    metadata_json TEXT NOT NULL DEFAULT '{}',
    created_at TEXT NOT NULL,
    FOREIGN KEY (job_id) REFERENCES translation_job(job_id) ON DELETE CASCADE,
    FOREIGN KEY (chunk_id) REFERENCES document_chunk(chunk_id) ON DELETE SET NULL
);
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| risk_type | 风险类型 |
| severity | `LOW / MEDIUM / HIGH` |
| message | 风险说明 |
| source_excerpt | 原文片段 |
| metadata_json | 来源 block、页码、bbox 和表格分组等 JSON 元数据 |

索引：

```sql
CREATE INDEX idx_risk_item_job ON risk_item(job_id);
CREATE INDEX idx_risk_item_chunk ON risk_item(chunk_id);
```

## 4. 关键约束

- `translation_job.job_id` 是任务主键。
- `document_chunk(job_id, chunk_index)` 唯一，保证分块顺序稳定。
- `term_entry(job_id, source_term)` 唯一，避免同一术语重复确认。
- `document_chunk.job_id`、`term_entry.job_id`、`risk_item.job_id` 外键关联任务。
- 删除任务时级联删除 chunk、术语、检查点、指标和风险项。

## 5. 状态流转规则

### 5.1 正常流转

```text
UPLOADED -> PARSED -> WAITING_TERM_REVIEW -> TRANSLATING -> COMPLETED
```

### 5.2 失败流转

任何执行阶段都可能进入：

```text
FAILED
```

失败后：

- 已完成 chunk 不回滚。
- checkpoint 保留。
- 可通过 `resume` 继续。

### 5.3 取消流转

运行中任务可进入：

```text
CANCELLED
```

取消后：

- 不再继续后台执行。
- 已完成中间结果保留。
- MVP 不支持从 `CANCELLED` 恢复。

## 6. 初始化建议

应用启动时执行：

```sql
PRAGMA foreign_keys = ON;
```

并创建所有表和索引。

MVP 使用应用启动时的轻量加法迁移，为已有 SQLite 数据库补充 `document_chunk` 和 `risk_item` 新列。该机制只允许新增带默认值的列，不负责重命名、删除和复杂数据回填。

进入多环境部署或出现非加法迁移前，必须引入 Alembic，并停止继续扩展手写迁移逻辑。

## 7. DocumentIR 与输出资产

### 7.1 文件系统作为结构存储

DocumentIR Lite 不直接拆成关系表，目标文件：

```text
storage/parsed/{jobId}/document.ir.json
storage/parsed/{jobId}/assets/
storage/outputs/{jobId}/manifest.json
storage/outputs/{jobId}/result.zip
```

原因：

- BlockIR、TableIR、FormulaIR 和 FigureIR 具有嵌套结构。
- 每次 Parser/Normalizer 处理后通常整体生成。
- MVP 不需要对任意单元格执行复杂 SQL 查询。
- 避免过早引入大量表和迁移负担。

DocumentIR 必须包含 `version`，工作流恢复时校验兼容性。

### 7.2 translation_job 目标增量字段（TODO）

以下字段尚未进入当前 ORM，实施 DocumentIR/输出增强时通过 Alembic 或受控加法迁移加入：

```sql
ALTER TABLE translation_job ADD COLUMN document_ir_path TEXT;
ALTER TABLE translation_job ADD COLUMN document_ir_version TEXT;
ALTER TABLE translation_job ADD COLUMN output_manifest_path TEXT;
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| document_ir_path | `document.ir.json` 路径 |
| document_ir_version | IR schema 版本，用于恢复兼容检查 |
| output_manifest_path | 输出文件与资产清单路径 |

原始文件继续使用 `original_file_path`，不复制到数据库。

### 7.3 document_chunk 目标增量字段（TODO）

混合切分需要增加可解释字段：

```sql
ALTER TABLE document_chunk ADD COLUMN section_path TEXT NOT NULL DEFAULT '[]';
ALTER TABLE document_chunk ADD COLUMN boundary_reason TEXT;
ALTER TABLE document_chunk ADD COLUMN boundary_score REAL;
ALTER TABLE document_chunk ADD COLUMN semantic_topic TEXT;
```

| 字段 | 说明 |
| --- | --- |
| section_path | JSON 数组，例如 `["Method", "Training"]` |
| boundary_reason | `SECTION_BOUNDARY / SEMANTIC_SHIFT / TOKEN_SOFT_LIMIT` 等 |
| boundary_score | 语义候选边界评分；硬边界可为空 |
| semantic_topic | 可选主题标签，不作为正确性依据 |

当前 `structure_metadata` 仍可承载试验字段；字段稳定后再提升为独立列。

### 7.4 TableIR / FormulaIR / FigureIR

这些结构存放在 DocumentIR JSON，不在 MVP 建独立关系表。

- TableIR 保存 cell、rowSpan、columnSpan、header、caption、footnote、confidence 和原图资产。
- FormulaIR 保存 LaTeX、编号、confidence 和原图资产。
- FigureIR 保存图片资产、caption、页码、bbox 和正文引用。

低置信度结构必须保留 `sourceAssetId`，以便输出原始证据。

### 7.5 manifest.json

输出 manifest 至少记录：

```json
{
  "version": "1",
  "files": [
    {
      "type": "bilingual_html",
      "path": "bilingual.html",
      "mediaType": "text/html"
    }
  ],
  "assets": [],
  "source": {
    "path": "original.pdf",
    "mediaType": "application/pdf"
  }
}
```

数据库只保存 manifest 路径，不重复存储整个清单。

manifest、IR 和资产路径必须是相对任务目录的规范化路径；禁止 `..`、绝对路径和盘符，数据库写入前执行路径边界校验。

### 7.6 迁移边界

当前手写迁移仅适合简单新增列。开始引入 IR 版本、输出 manifest 和混合切分字段前，应优先接入 Alembic，避免持续扩大手写迁移职责。
